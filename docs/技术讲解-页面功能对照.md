## 二、关键技术点（短说）

**1. 主链路为什么不经 LLM？**
核验的可信度来自"答案里的每个数字都逐字存在于原文"。这条链是确定性的：检索取候选 → span 比对原文 → 坐标定位到那一行 → 组装六元组。LLM 不参与取值与算术，所以它编不了数字；Agent 只在最前面做意图与工具选择那一环。

**2. 防幻觉怎么落地**
证据片段必须逐字出现在原文（第一关），且数值必须能从片段解析出来（第二关）。演示台把同一条证据喂三次：真值采纳、改数字拦截、伪造片段拦截——第二例最危险，因为片段是真的。

**3. 勾稽核验**
报表内部有恒等式（如资产 = 负债 + 权益）。不平不一定是造假，但值得追查。容差由披露单位推导，不硬编码 0.01。

**4. 它到底是不是 Agent**
四要素（LLM + 工具 + 记忆 + 控制流）都齐，但它是"受限编排 Agent"：LLM 唯一权力是在合法后继里挑一个节点名，不能填参数、不能改数值、不能决定拒答。六元组缺字段时程序级拒答，模型无否决权。

**5. 多报告与元数据**
每份报告 = 已解析年报 + 检索索引。公司名 / 期间 / 单位从文档自身读出，不再硬编码。新增报告只在 `DOC_CONFIGS` 登记一项 + 建索引，端点逻辑不动。

## 三、已知边界（诚实说明）

- 演示用预解析的 p58–67 切片，不是全本；上传任意 PDF 自解析待接。
- 向量通道走本地 TF-IDF（端点无 embedding）；扫描版 PDF 需先 OCR。
- "资产负债率"等比率目前只校验分子分母，比率本身待补 F7。
- 口语简称（如"经营现金流"）可能静默命中子科目行（见 P-030），检索侧根治待做。
