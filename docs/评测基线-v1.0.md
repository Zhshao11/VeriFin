## 一、一句话结论

**29 题通过 21 题（72.4%）。**
其中**可答题 18/22**、**应拒答正确 3/7（误答 4 题）**、**`ABORT` 0**。

## 二、环境与复现

```bash
.venv/bin/python -m verifin.eval.gold_check        # 标注自检：29/29
.venv/bin/python -m verifin.eval.run_eval          # 基线：21/29
```

| 项 | 值 |
|---|---|
| 文档 | 贵州茅台 2024 年年度报告（`data/pdfs/MOUTAI_2024_ANNUAL.pdf`） |
| 解析窗口 | p58 – p67（**仅财务报表章节，不是全文**） |

**为什么解析窗口不是全文**：MinerU 默认只解析前 10 页，本数据集刻意限定在财务报表章节（p58–p67）内。
这个选择有代价 —— 它会**人为制造**一批"信息不在窗口内"的应拒答题（见 §五 的 `out_of_parse_window`）。
报告必须写明，否则会被误读为系统检索能力不足。

## 四、基线结果

### 4.1 总览

| 指标 | 结果 |
|---|---|
| **总通过率** | **21 / 29（72.4%）** |
| 可答题 | 18 / 22 |
| 应拒答正确 | 3 / 7（误答 4） |
| `ABORT` | **0** |

### 4.2 按题型

| 题型 | 通过 / 总数 | 说明 |
|---|---|---|
| 单值抽取 L1 | **14 / 15** | 唯一失败项是母公司口径（B-015） |
| 勾稽 / 计算 L2 | **4 / 5** | 唯一失败项也是母公司口径（B-017） |
| 综合判断 L3 | **0 / 2** | 系统不具备"求差 / 聚合"能力，且 gold 未迁就能力（见 §六） |
| 应拒答 R | **3 / 7** | 4 题误答，见 §五 |

### 4.3 按口径

| 口径 | 通过 / 总数 |
|---|---|
| 合并 | **18 / 19** |
| 母公司 | **0 / 2** |
| 跨口径 | **0 / 1** |
| 不适用（R 题） | 3 / 7 |

**"母公司 0/2"是本基线最干净的一条信号**：系统在合并口径下几乎全对（18/19），
一旦问句点名母公司口径就全错 —— 说明**缺陷在口径识别，不在取数能力**。

### 4.4 失败分类

| 分类 | 题数 | 题号 |
|---|---|---|
| 数值错 | 3 | B-015、B-021、B-022 |
| 操作数取错 | 1 | B-017 |
| 误答（本该拒答） | 4 | B-024、B-025、B-028、B-029 |
| 页码不符 | 0 | — |

**"页码不符 0 题"值得单独说**：所有答对的题，数值与页码**同时**正确。
这说明证据链（六元组的"来源"字段）没有系统性偏移。

### 4.5 降级与 LLM 参与度

```
LLM 步 0/128（0.0%）   含兜底步的运行 29 次
```

本次基线**全部 29 次运行、128 个决策步，没有一步是 LLM 决定的**。
这正是 §七 要解释的：**这不是"LLM 没效果"，而是"LLM 压根没被调用"**。

## 五、失败逐条分析

### 5.1 母公司口径（2 题）—— 已知设计缺口，不是意外

| 题号 | 问 | 期望 | 实得 | 性质 |
|---|---|---|---|---|
| B-015 | 母公司资产负债表的资产总计 | 180,236,524,477.01 | 298,944,579,918.70（合并值） | 口径取错 |
| B-017 | 母公司资产总计 = 负债 + 权益？ | 操作数取母公司三个值 | 三个操作数**全部**取了合并值 | 口径取错 |

**根因**：检索层对同科目名的合并 / 母公司两条记录**不做区分**，
`by_label` 用 `setdefault` 取**首次出现**（合并表在前）→ 永远取合并值。

**关键点**：B-017 的判定结果是 **PASS**（母公司恒等式也平衡，差额 0.00）。
如果判分只看 `PASS`，**这题会被判成对** ——
这正是 §六.2 那条"先比操作数再比判定"的规则存在的理由。本基线的判分实现拦住了它。

**当前决定**：暂不实现口径消歧，如实记录为缺口。
理由是它需要一次**数据结构变更**（chunk 携带报表口径标签），
而不是加个 if —— 属于设计决策，留到多口径评测集时统一处理。

### 5.2 综合判断（2 题）—— 系统能力边界

| 题号 | 问 | 期望 | 实得 | 性质 |
|---|---|---|---|---|
| B-021 | 归属于母公司股东的净利润 **与** 净利润的**差额** | 3,106,581,604.28 | 86,228,146,421.62 | 不会求差 |
| B-022 | 母公司口径资产总计 **与** 合并口径相差多少 | 118,708,055,441.69 | 298,944,579,918.70 | 不会求差 + 口径 |

**根因**：系统当前只有"取一行"和"套公式"两种动作，**没有"两行相减"这个动作**。
两个数都能取到，但问句要求的是它们的差。

**这里 gold 没有迁就系统**：期望值是"一个称职 analyst 会给出的答案"。
如果按系统能力把 gold 改成"无法回答"，评测就退化成"系统跟自己对答案"。
这类失败**应当**出现在基线里，它标出的是能力边界，不是标注错误。

### 5.3 拒答护栏的 4 个缺口（最重要的一节）

4 道应拒答题被**作答了**。逐题看它们其实是**4 个不同的缺口**：

| 题号 | 问 | refusal_reason | 系统实际行为 | **缺的是哪一道护栏** |
|---|---|---|---|---|
| B-024 | 贵州茅台**2025 年第一季度**营业收入 | `out_of_document_period` | 答"2024 年度 营业收入 = 170,899,152,276.34" | **期间约束不校验** |
| B-025 | **宁德时代**2024 年营业收入 | `wrong_document` | 答"2024 年度 营业收入 = 170,899,152,276.34" | **主体约束不校验** |
| B-028 | 合并现金流量表**现金及现金等价物净增加额** | `out_of_parse_window` | 答"**投资活动现金流入小计** = 8,648,630,396.52" | **问答不对齐（最危险）** |
| B-029 | **资产总计**是多少？ | `ambiguous_scope` | 答"298,944,579,918.70"（默认合并） | **口径歧义不拒答** |

**B-028 是四条里最严重的一条，必须单独说清**：

系统被问「现金及现金等价物净增加额」，返回的六元组里**指标字段写的是「投资活动现金流入小计」**
—— 它**答的是另一个问题**。数值 8,648,630,396.52 本身在 PDF 里真实存在、页码也正确，
span 校验一路通过。

也就是说：**现有的全部护栏（span 校验、Decimal、页码溯源）都拦不住它**，
因为它们校验的是"这个数是不是原文里的"，而不是"这个数是不是**问句问的**那个"。
这是一整类此前未被覆盖的失败模式，也是本基线最有价值的发现。

**为什么另 2 道 `out_of_parse_window`（B-026 签字号、B-027 研发人数）却正确拒答了**：
它们问的科目在索引里**根本不存在**，label 与 lexical 通道双空 → 触发 `NO_RECALL`。
而 B-028 问的科目（"现金及现金等价物净增加额"）**部分命中**了
"投资活动现金流入小计"等邻近行 → 召回了不该召回的证据 → 没有任何机制发现答非所问。

> 一句话归纳这 4 条：**当前的拒答判据只有"有没有召回到证据"，没有"召回到的证据对不对得上问句"。**
> 护栏的判别力止步于"证据存在性"，未延伸到"问答一致性"。

## 六、由评测暴露并已修复的 7 个缺陷

D4 的评测不是"跑个分"，它的主要产出是**把 7 个此前不知道的缺陷逼了出来**。
逐条详情见 `docs/技术问题留档.md`。

| # | 缺陷 | 现象（评测中暴露） | 修复 |
|---|---|---|---|
| P-016 | 不可用的候选证据被**无限重试** | 单题吃光 12 步预算 → `ABORT` | `EVIDENCE` 节点在**失败分支也记录 `tried`** |
| P-017 | 停用词只过滤了查询侧，**未过滤切词结果** | "火星基地…折旧年限"与文档余弦 **0.40**（只因共同"的"）→ 弱通道产生假召回，**掏空拒答护栏** | `tokenize` 内过滤停用词 + **强/弱通道分离**（vector 只重排、不产生召回） |
| P-018 | label 通道**只做整串相等** | 真实问句永远不命中 → 主召回通道形同虚设 | 增加"科目名被问句包含"匹配（最长优先） |
| P-019 | 公式触发表**只覆盖 F1** | F2a/F2b/F3a/F4/F6 永远走不到 | 补齐 `FORMULA_HINTS`（含每公式要求的关键词数） |
| P-020 | `F4` 的操作数里**含派生的左值** | 毛利率题永远缺操作数，判成 `WARN` | 新增 `Formula.required_operands` |
| P-021 | 报表披露名 ≠ 公式操作数名 | "实得 None"的假失败 | 操作数键与报表行名分离（对齐现有 `LABEL_ALIAS`） |
| P-022 | 运行时装配**在 3 处重复** | 演示 / Web / 评测三份装配代码，改一处漏两处 | 收敛到 `verifin/runtime.py` 单一入口 |

### 6.1 迭代记录

| 轮次 | 通过率 | 变化原因 |

P-017/P-018/P-019 这三条尤其典型：它们让**主召回通道和公式触发表实际上处于关闭状态**，
而在此之前没有任何测试发现 —— 因为单元测试都在测"给定输入有没有正确输出"，
**没有一个测试问"这条通道在真实问句上还会不会触发"**。
评测的价值正在于此。

## 七、为什么基线不接 LLM（这不是降级）

```
LLM 步 0/128（0.0%）
```

这是**刻意**的：

1. **红线 #1～#3（LLM 不产数 / 不算术 / 不决定拒答）只有在没有 LLM 的环境里才能被证明。**
   接上 LLM 跑一遍，无法区分"结果是确定性链路算出来的"还是"模型给的"。
2. **确定性链路必须先独立达标**。否则一旦结果不好，无法归因是检索/计算的问题还是编排的问题。
3. 基线的作用是**建立下界**：72.4% 是"完全不借助模型"的下界。
   接上 LLM 调度器（`--planner llm`）后若**低于**它，说明模型在拖后腿 —— 这个对比才有意义。

**因此报告里不能说"LLM 参与度低 = LLM 没用"** —— 本次它压根没被调用。
这正是 P-015（LLM 预算被写全局计数导致静默降级）留下的教训，也是 `run_eval` 强制从轨迹 `source` 字段读降级率的原因。

## 八、这套结果证明了什么 / 没证明什么

### ✅ 证明了

| 结论 | 依据 |
|---|---|
| `Decimal` + 公式注册表的勾稽核验在真实年报上可用 | L2 4/5 通过，且 B-017 的"操作数取错"被正确拦下 |
| 证据链（页码）无系统性偏差 | 页码不符 **0** 题 |
| 拒答是程序状态、能触发 | R 题 3/7 正确拒答；`ABORT` 为 0（不靠预算耗尽"假装拒答"） |
| 判分设计能识破"取到真数、答错题" | B-017 判 PASS 但操作数取错 → 仍记失败 |
| 护栏的可证明性 | 全部 29 题在**零 LLM**环境下跑通 |

### ❌ 没有证明

| 不能说 | 原因 |
|---|---|
| "拒答率 43%" | 分母只有 7 题，且其中 2 题是**解析窗口人为造成**的，样本量不足以给出比率结论 |
| "支持并发评测" | 调度器已按请求隔离、轨迹库已加锁并有并发单测，但**未做并发压测**，只能说"逻辑可证" |
| "能处理多公司" | 六元组的公司 / 期间**仍取自演示配置**，未从 PDF 封面解析 |
| "LLM 编排有效 / 无效" | 本次 LLM 调用 0 次，无从判断 |
| "综合判断能力 0%" | 只有 2 题，且 gold 未迁就系统能力；这是能力边界的**样本**，不是比率 |

## 九、下一步（按优先级）

| 序 | 工作 | 理由 |
|---|---|---|
| 1 | **补「问答一致性」护栏** | B-028 那一类（答非所问）现有护栏**全部拦不住**，是最大风险 |
| 2 | 补主体 / 期间约束校验 | B-024 / B-025，问句点名的主体与期间必须与文档核对 |
| 3 | 口径消歧（chunk 加报表口径标签） | B-015 / B-017 / B-022；需数据结构变更，不宜打补丁 |
| 4 | "两行相减"动作 | B-021 / B-022；L3 能力缺口 |
| 5 | Track A（FinanceBench 50 题） | 对齐公开可比基线 |
| 6 | 消融 V0 / V1 / V2 | 依赖 5 |

**其中第 1 项建议立刻做**：它不是"提高准确率"，而是**堵住一条把错误答案伪装成正确答案的通道**。
B-028 的数值真实、页码真实、span 校验通过 —— 目前只有人工比对问句才能发现它答错了题。
