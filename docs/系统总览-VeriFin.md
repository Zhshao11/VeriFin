# VeriFin · 系统总览

> 一句话：**A 股年报财务数字的可溯源核验 Agent**——问一个财务数字，要么给出能点回原文页码与行坐标的答案，要么程序级拒答，不存在"既不可溯源又强行作答"的中间态。
> 定位：校招面试项目 ｜ 仓库 `Zhshao11/VeriFin` ｜ Python 包 `verifin` ｜ Apache-2.0
> 更新：2026-09-21 ｜ 数字口径以 `docs/评测基线-v1.0.md` 与仓库代码为准

---

## 一、项目背景

### 要解决的问题

大模型做财报问答有一个**致命但被普遍忽视**的缺陷：它给出的数字**看起来对、格式也对，但查不到出处，错了也无法定位**。

- 财务场景里，"数字错了"的代价不是"体验差"，是**误导决策**；
- 通用做法（把年报丢给 LLM 直接问）有两个无法回避的问题：① 数字是模型"生成"的，不是从原文"取出"的；② 即使答对，也无法验证——你没法让审计方相信一个没有出处的数。

### 面向的用户与场景

审计、投研、财务尽调等需要**核对年报原值**的场景。用户拿着一份年报问"营业收入是多少"，要的不只是数字，而是"这个数字出自第几页哪一行"。

### 项目的核心判据（自定，也是面试问答的锚点）

> 给它一份年报和一个财务问题，它要么给出每个数字都能点到 PDF 具体页码与原文片段的答案，要么明确拒答。**中间不允许编造。**

## 二、系统介绍

### 是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 一个带**证据链**的核验系统：每个数字可回溯到页码 + 行坐标 | 不是"让大模型读年报然后回答"的套壳 RAG |
| 一个**受限编排 Agent**：LLM 只做路由，不产数、不算术、不决定拒答 | 不是让 LLM 自主调用工具、自由生成参数的自主 Agent |
| 一个**可复现的评测对象**：有题库、有判分口径、有基线 | 不是"跑通一个 demo 就算完成" |

### 四要素（回答"这算不算一个 Agent"）

**Agent = LLM + 工具 + 记忆 + 控制流**，四者本项目都齐 → **是 Agent**；但它是**"受限编排 Agent"**：

- **LLM**：唯一权力是在图的"合法后继"里挑一个**节点名**；
- **工具**：8 个确定性工具（检索 / 校验 / 定位 / 计算 / 求差 / 约束检查）；
- **记忆**：执行轨迹落 SQLite（run/step 两级，可回放）；
- **控制流**：12 节点显式图 + 三重预算（`max_steps=12 / max_tool_calls=10 / max_llm_calls=8`）。

> 讲给面试官：**"我们不是让 LLM 去算账，而是让 LLM 在受约束的图里选下一步；取值、算术、拒答判定全部走确定性代码。"**

### 端到端链路

```
用户提问
   │
   ▼
[INTENT] 意图分类 ──────────────► [GUARD] 主体/期间/口径约束检查
   │                                      │
   ▼                                      ▼
[SEARCH] 四路召回 ─────────────► [EVIDENCE] 候选证据筛选
   │  label/lexical/numeric/vector
   │  → RRF(k=60) 融合                   │
   ▼                                      ▼
[VERIFY_SPAN] 原文逐字校验 ─────► [LOCATE] PyMuPDF 同行坐标定位
   │  ① 片段在原文中逐字存在
   │  ② 数值可从片段解析                 │
   ▼                                      ▼
[LIST_FORMULAS]/[COMPUTE]/[DIFF] ─► [ANSWER] 装配六元组
   │  公式注册表 F1–F6 / 两行相减        或
   ▼                                    [REFUSE] 程序级拒答
六元组：公司 ｜ 期间 ｜ 指标 ｜ 数值 ｜ 单位 ｜ 来源(页码+坐标)
```

## 三、系统设计的主要考虑点

这是全项目最值钱的部分——**每一个设计决策都对应一条"想清楚了才会这么做"的取舍**。

### 考虑点 1：把 LLM 的权力压到最小（红线 #1/#2/#3）

**问题**：让 LLM 调用工具，工具参数就必然由 LLM 生成。而 `verify_span(claimed_value=...)` 的参数**就是待校验的数值**——一旦 LLM 填这个参数，"用原文校验数值"就退化成"**用 LLM 的数校验 LLM 的片段**"，护栏形同虚设。

**决策**：推翻原选的 Pydantic AI + function calling 方案（留档 P-013），改为**自写显式图 + "LLM 只选节点名、工具入参由图从 state 填"**。LLM 彻底失去产出数值的能力。

> 注：该否决是**范式判断**，非实测结论（从未实测过 Pydantic AI），汇报时如实说明。

### 考虑点 2：拒答是一等程序状态，不是提示词约定

**问题**：把所有约束写进 system prompt 让模型"别乱答"，等于**信任模型遵守规则**——而这恰恰是不可信的。

**决策**：六元组**缺任何一个字段即程序级拒答**，模型无权否决。并把拒答细分：

| 状态 | 含义 |
|---|---|
| `REFUSE` | 证据不足（这是正确的拒答） |
| `ABORT` | 预算耗尽没算完（**不等于拒答**，混进拒答率会掩盖规划器缺陷） |

### 考虑点 3：口径（合并/母公司）必须在取数前消歧

**问题**：中文年报里同名科目在**合并表**和**母公司表**各有一行，数值完全不同但都是真数字。检索若"谁先出现取谁"，会安静地给出另一张表的数。

**决策**：口径识别集中在 `verifin/scope.py`（表格/检索/编排/评测四处一律调用，各写一份必漂移）；**口径歧义在取数之前判定**——两套都有且问句未限定 → `AMBIGUOUS_SCOPE` 拒答。

### 考虑点 4：两类护栏的取舍刻意相反

| 护栏 | 判断不了时 | 为什么 |
|---|---|---|
| 主体 / 期间约束 | **放行** | 误拦会把**正确回答变成拒答**，损失真实可用性 |
| 问答一致性 | **拒答** | 给错一个财务数字，后果不是"体验差" |

### 考虑点 5：检索为什么是四路 + RRF，而不是单路

- **label**（精确科目名）：解决 BM25 不区分完整匹配与子串匹配（"负债合计"被"非流动负债合计"抢走）
- **lexical**（FTS5 + jieba）：词面召回
- **numeric**（Decimal 精确）：纯数字查询——BM25 会把大数切碎，必须单独成路
- **vector**（本地 TF-IDF）：软匹配兜底（端点无 embedding，见下）

用 **RRF(k=60)** 融合而非加权求和：三路分数量纲完全不同，直接相加等于让某一路主导；RRF 只看名次，天然规避归一化问题。

### 考虑点 6：熔断 > 降级，且二者顺序不能反

**问题**：网络抖动与"端点不支持某参数"是两类问题，若写在同一个 except 里，**一次瞬时 429 会被升级成一次永久能力降级**（留档 P-027）。

**决策**：拆成两层，**顺序固定**——内层有界重试（指数退避 + 抖动 + `Retry-After`），外层才做能力降级。可重试分类刻意排除 401/403/404/400（重试不会变对，只会拉长失败时间）。

### 考虑点 7：评测的判据必须选对，否则等于没测

三条设计（留档 P-028 等）：
1. **对抗集要求"照常给真值"而非"拒答"**——一个把所有问题都拒答的废系统能拿满拒答分；
2. **跑反向对照**——把 gold 换成假值，评测**必须失败**，才能证明正向通过不是假绿；
3. **gold 第三道闸门只读原始 PDF**——排除"解析器错了、标注跟着一起错"的自洽型错误。

## 四、核心卖点

按"面试官只给 30 秒先讲哪个"排序：

### 卖点 1（最硬）：让 LLM 只路由、绝不产数，且**可证明**

不是口号——在**零 LLM 环境**下 40 题全部跑通（Track B 33 题 + Track D 对抗 7 题）。这是别的项目做不到的：它们"接上大模型答对了"**无法归因**（数字是模型给的还是代码算的？）；本项目能在没有 LLM 的进程里证明核心能力成立。

### 卖点 2：可溯源到**行坐标**，不是 chunk 级

六元组的"来源"是页码 + 行坐标 `(x0,y0,x1,y1)`，数字能被人肉眼点回原文那一行并高亮。这是**可审计**的结构性保证，不依赖任何判据。

### 卖点 3：想清楚了"财务数字问答到底会怎么错"

不止"答不出"，还有更难防的——**数值真、页码真、但答的是另一个问题**（B-028：问「现金及现金等价物净增加额」返回「投资活动现金流入小计」）。于是把拒答判别力从"证据存在性"推到"**问答一致性**"。

### 卖点 4：评测是"能逼出缺陷的评测"，不是跑分

一轮评测**逼出 7 个单元测试从未发现的缺陷**。原因：单测问"给定输入有没有正确输出"，评测问"这条通道在真实问句上还会不会触发"——两种东西。

### 不当作卖点的（讲会被戳）

- MinerU / jieba / FTS5 是**选型**不是发明；
- "自建题库 100%、N 个单测全绿"是**自我参照指标**，含金量≈0；
- **FinanceBench 从未跑过**，只能说"判分口径对齐其 Exact Match"，不能暗示跑过。

### 按层功能清单

**核验主链路（确定性，不经 LLM）**
四路召回 → RRF(k=60) → span 双层硬校验 → PyMuPDF 同行坐标定位 → 六元组装配 / 程序级拒答。

**解析层**
MinerU 4.0.3 出表格与页码；PyMuPDF 出绝对坐标；跨页表格拼接（续页重复表头、按科目名合并、保留每行来源页码）；降级链 MinerU → Docling → pdfplumber → PyMuPDF。

**检索层**
四路召回 + RRF；财务专用词典（约 140 条）注入 jieba；纯数字查询走 Decimal 精确匹配。
> 实测对比：固定 15 个易碎科目名、同一问句模板，词典开关两态的端到端检索 top-1 命中率 **26.7%（4/15）→ 100%（15/15）**（脚本 `scripts/measure_lexicon_ablation.py`）。

**编排层**
12 节点 / 8 工具显式图（`GRAPH`）；LLM 只选节点名；三重预算按次运行重置；降级一律标 `source="policy"` 且不掩盖；执行轨迹落 `data/index/agent_trace.db` 可回放。

**口径与护栏层**
口径识别集中 `scope.py`；口径歧义/问答一致性/主体约束/期间约束四类护栏；`DIFF` 节点 + `diff_two_rows`（两行相减是独立动作，不套公式）。

**评测层**
`verifin/eval/`：schema / bank / docs / gold_check（三闸门 + CLI）/ run_eval（判分 + CLI）；判分**先比操作数再比判定**；`ABORT` 与 `REFUSE` 分开统计。

**Web 演示层**
`web/server.py` + `web/index.html`：多报告（茅台 2024 / 2023）+ 用户视角 UI（Hero → 报告卡片 → 提问 → 答案卡含大数字 + "已逐字核对原文"绿标 + 高亮原文截图），技术细节折叠。

**文档层**
`docs/` 含：项目上下文速览、技术选型、评测方案与基线、技术问题留档（P-001~P-030）、真实财报问题示例、技术讲解-页面功能对照。

### 已知边界（诚实声明，面试被问要有准备）

- **不承诺"不幻觉"**：只能降低概率、缩小影响面、加快定位。
- 解析窗口是**评测的隐含前提**：本数据集只解析 p58–p67，`out_of_parse_window` 类拒答题是**人为制造**的，不写清会被误读成检索能力不足。
- 六元组的公司/期间已由 runtime 从文档自动识别；**单位**是真从解析产物读的（`单位:` 声明）。

## 七、不可违反的设计红线

1. **LLM 不产生任何数字** —— 数值只能来自 span 校验通过的原文
2. **LLM 不做任何算术** —— 算术全部走 `Decimal` + 公式注册表
3. **LLM 无权决定拒答与否** —— 六元组缺字段即程序级拒答
4. **embedding 不参与数字精确匹配** —— 必须先做数字归一化（去千分位 / 全角半角 / 单位分离）

> 这 4 条是"这个项目为什么不是套壳 RAG"的答案。任何设计不得削弱它们。
