## 一、这份方案要挡住的四件事

评测方案的价值不在于"有个分数"，而在于**它能把哪几类错误变成可判定的失败**。
本项目最想挡住的四类，恰好就是四条设计红线的反面：

| # | 要挡住的错误 | 若没有对应的评测设计会怎样 |
|---|---|---|
| 1 | **数值编造** | 只要"数字看起来合理"就得高分，护栏形同虚设 |
| 2 | **取错报表口径**（合并 / 母公司） | 取到的是真数字，但答的是另一张表 —— **最难发现**，因为数值本身真实存在 |
| 3 | **本该拒答却作答** | 拒答率失去分母，护栏"生效"变成自我宣称 |
| 4 | **降级被掩盖** | 报告写"LLM 参与度低"，其实是 LLM 压根没被调用（P-015 的教训） |

其中第 2 条是本项目的"签名错误"，方案里专门为它设计了一条判分规则（见 §六.2）。

## 三、题型分层

| 层 | 名称 | 期望结局 | 考察能力 |
|---|---|---|---|
| **L1** | 单值抽取 | ANSWER | 精确检索 + 数字定位 + 页码溯源 |
| **L2** | 勾稽 / 计算 | ANSWER | 多证据聚合 + `Decimal` 计算 + 公式判定 |
| **L3** | 综合判断 | ANSWER | 多陈述推理（可能涉及跨口径 / 跨表） |
| **R** | 应拒答 | REFUSE | 护栏：该拒就拒，不多不少 |

**期望结局只有两种**（`ANSWER` / `REFUSE`）。原方案设计 §8 里讨论过的"部分答案 + 显式标注 missing"**不进题库** —— 它会让拒答率的分母口径含糊（"给了一半"算答对还是算拒答？）。先在题目层面把结局二值化，部分答案的能力单独评估。

**L3 的 gold 来自"一个称职分析师会给出的答案"，不迁就系统当前能力。**
这是刻意的：如果 gold 按系统能力裁剪，评测就退化成"系统跟自己对答案"。
系统做不到的 L3 题会如实记入失败清单（基线里正是如此）。

## 四、口径：中文年报特有的第三个维度

中文年报**同一科目名有两套数值**：

```
资产总计（合并）  = 298,944,579,918.70
资产总计（母公司）= 180,236,524,477.01
```

方案把口径单列成一维（`合并` / `母公司` / `跨口径` / `不适用`），并定下两条规则：

1. **可答题的 `scope` 必须与问句点名一致**（程序级校验）。
   问句里出现"母公司"就必须标 `母公司`，否则评测会把**取错口径记成算错数**。
   注意排除 **「归属于母公司」** —— 它是合并报表的科目名（归属于母公司股东的净利润），
   名字带"母公司"但和母公司报表无关；用朴素子串判断会把合并题误判成口径不一致，**误报比漏报更消耗信任**。
2. **`跨口径` 单列，不并进 `不适用`。**
   "合并与母公司口径的资产总计相差多少"这类题**有明确口径（两个都要）**；
   标成"不适用"会让报告分不清"这题本来就不涉及口径"和"这题涉及两个口径"。

## 五、题库的字段契约（`verifin/eval/schema.py`）

题库质量不能靠"看起来对"。下列约束全部是**程序级**的，不满足即 FAIL：

| 约束 | 理由 |
|---|---|
| 标为 `REFUSE` 的题**不得带任何 gold**（值 / 单位 / 判定 / 操作数 / 页 / 片段） | 否则"本该拒答"被标注成一个具体答案，拒答率的分母失去意义 |
| `expected_outcome=REFUSE` ⟺ `question_type=R` | 否则拒答率的分母口径会乱 |
| 可答题必须带 `gold_pages` + `gold_evidence` | 没有页码与片段，"来源可溯源"这条能力就没被考 |
| 判定型题（恒等式 / 启发式）必须带 `gold_verdict` **且** `gold_operands` | 见 §六.2 |
| 数值型题必须带 `gold_value` 且必须带 `gold_unit` | 少单位＝把"元 / 万元"的差异放过 |
| `gold_verdict` 与 `gold_value` 不得同时出现 | 判定型与数值型二选一，避免判分口径含糊 |
| `gold_operands` 只允许 L2 / L3 | L1 的答案就是报表上那一行，不需要另标来源值 |
| 页码一律 1-based 且 ≥ 1 | `doc[page-1]` 在 `page=0` 时会被负索引解释成最后一页 |
| 题号唯一 + 同一文档下问句不重复 | 重复题会污染统计 |

> 逐条检查**刻意不用异常**：一次要把全部问题都列出来，而不是遇到第一条就停 ——
> 修标注要来回跑很多轮，一次只报一条会让人崩溃。

## 六、判分口径的三个决定

### 6.1 数值与页码**分开报**

数值对、页码错，和数值错是**两种故障**：前者是证据链的问题，后者是取数的问题。
合成一个"正确/错误"会把故障类型丢掉。基线报告里因此单列"页码不符"这个失败分类。

### 6.2 判定型题：**先比操作数，再比判定**（本项目的签名错误）

同一恒等式在**两套口径下都能平衡**：

```
合并：   298,944,579,918.70 = 56,933,264,798.10 + 242,011,315,120.60   差额 0.00  PASS
母公司： 180,236,524,477.01 = 15,750,242,139.09 + 164,486,282,337.92   差额 0.00  PASS
```

**两行都 PASS。** 所以：

- 若判分只看 `PASS`，用母公司数据去算合并恒等式**会被判成对** ——
  而这正是"取到真数、答错题"这类最隐蔽的错误。
- 故判定型题必须同时标注 `gold_operands`（参与运算的**原值**），
  判分顺序为 **操作数 → 判定**，操作数错就直接记 `操作数取错`，不再看判定。

> 操作数键用**公式的操作数名**（如 `所有者权益合计`），不是报表的披露行名
> （报表里叫 `所有者权益（或股东权益）合计`）。
> 两者靠 `LABEL_ALIAS` 对齐；早期混用导致"实得 None"的假失败。

### 6.3 `ABORT` **不算**拒答成功

- `REFUSE` = 证据不足（护栏生效）
- `ABORT` = 预算耗尽，没算完（规划器缺陷）

把 `ABORT` 计入"正确拒答"，等于把规划器缺陷伪装成护栏生效。基线报告里 `ABORT` 单独一列。

## 七、gold 自检：三道独立闸门

题库最大的风险不是漏题，是**标错** —— gold 页填错、gold 值抄错。
标错的题会把系统的**正确行为判成错误**（假阳性），比漏题危险。

| 闸门 | 检查什么 | 为什么不能省 |
|---|---|---|
| **G1 索引页** | gold 值能在 `gold_pages` 中某一页的检索块内找到 | 证明"确实有一页承载这个数" |
| **G2 证据片段** | 每个 gold 片段能在**同一页**原文里定位 | 证明片段属实，不是凭印象写的 |
| **G3 PDF 原件** | gold 值能在**原始 PDF** 该页的文本层里找到 | **三道中唯一独立于本项目解析产物的** |

**G3 是整套自检的支点**：只有它通过，才能排除"解析器错了、标注跟着一起错"这种自洽型错误。

**派生量题特例**：像毛利率 91.93% 这种**算出来的**答案在 PDF 里根本不存在，
所以带 `gold_operands` 的题，G1/G3 校验的是**操作数**而不是答案本身。

自检顺带记录一个信息量很大的字段 —— `value_pages`（该数值在全文出现的**所有**页）：

- 只出现在 gold 页 → 这道题**能区分口径**
- 出现在多页 → **光比数值不足以判对错，必须同时比页码**

## 八、指标体系（分子 / 分母写清）

对齐方案设计 §6.3，v1.0 已实现前五项：

| 指标 | 定义 | 状态 |
|---|---|---|
| **单值核验准确率** | 数值在容差内 **且** 引用命中 gold 页码 的题数 / L1 题数 | 🟢 已实现 |
| **勾稽核验准确率** | 操作数正确 **且** 判定正确 的题数 / L2 题数 | 🟢 已实现（按 §六.2 加强） |
| **综合核验准确率** | 多陈述综合判断与 gold 一致的题数 / L3 题数 | 🟢 已实现 |
| **拒答率** | 正确拒答数 / 应拒答题总数（**单独报，不混入总分**） | 🟢 已实现 |
| **证据召回率** | 每题 top-k 命中 gold 页码的证据数 / 标注证据数 | ⬜ 待实现（需检索层暴露候选列表） |
| **引用支持度** | 抽查的「引用—结论」对中证据确实支持结论的比例 | ⬜ 待实现（需 LLM 复核，注意红线 #1：只做复核不做取数） |
| **端到端耗时** | P50 / P95，注明失败任务口径 | ⬜ 待实现 |
| **单次查询成本** | 所有 LLM 调用成本之和，注明模型与价格日期 | ⬜ 待实现 |

**另加两项本方案自行设定的指标（不在原 §6.3 里，但必须有）**：

| 指标 | 定义 | 为什么必须有 |
|---|---|---|
| **降级率** | 轨迹里 `source="policy"` 的步数 / 总步数 | 不读它就会重犯 P-015：「看起来 LLM 没效果、其实它压根没被调用」 |
| **`ABORT` 率** | `ABORT` 次数 / 总运行数 | 与拒答率分开统计，见 §六.3 |

## 九、应拒答题的 5 类原因（机器可读）

R 题的 `refusal_reason` 以**固定的英文前缀**开头，便于统计"哪一类护栏缺失"：

| 前缀 | 含义 | 例 |
|---|---|---|
| `no_recall` | 文档中不存在该主体与科目，四路召回均无命中 | 火星基地 2024 年折旧年限 |
| `out_of_document_period` | 问句点名期间超出文档覆盖期间 | 贵州茅台 **2025 年第一季度**营业收入 |
| `wrong_document` | 问句点名主体不是本文档主体 | **宁德时代** 2024 年营业收入 |
| `out_of_parse_window` | 信息存在，但不在已解析页范围内 | 研发人员数量（在"员工情况"章节） |
| `ambiguous_scope` | 同科目在合并 / 母公司两套口径下数值不同，问句未限定口径 | **资产总计**是多少 |

**为什么前缀要机器可读**：拒答率是一个数，但"错在哪种护栏"是诊断信息。
`no_recall` 失败指向检索层，`out_of_document_period` 失败指向**约束校验层**，两者的修法完全不同。

## 十、复现命令

```bash
# 1) 格式与一致性校验 + 生成题库（--dry-run 只校验不写盘）
.venv/bin/python scripts/build_eval_bank.py --dry-run

# 2) gold 三道闸门自检（G3 会打开真实 PDF，不需要额外产物）
.venv/bin/python -m verifin.eval.gold_check
.venv/bin/python -m verifin.eval.gold_check --json /tmp/gold.json

# 3) 跑评测基线（确定性策略，不需要 LLM）
.venv/bin/python -m verifin.eval.run_eval
.venv/bin/python -m verifin.eval.run_eval --tier L2 --all
.venv/bin/python -m verifin.eval.run_eval --json /tmp/eval.json

# 4) 换 LLM 调度器再跑一遍（需 .env 凭证）
.venv/bin/python -m verifin.eval.run_eval --planner llm
```

`run_eval` 的退出码为 0 仅当**全部通过**，可直接用于 CI 卡口。

## 十一、已知限制（必须写进任何引用本方案的地方）

1. **六元组的「公司 / 期间」仍取自演示配置**，未从 PDF 封面结构化解析（指标、数值、单位、页码都是确定性的）。多公司评测集建成后会暴露为问题（P-012 残留）。
2. **单文档评测**：Track B 目前 1 家公司 1 份年报。跨年对比题依赖的 `MOUTAI_2023` 已下载 PDF 但**未解析未建索引**，暂不可评测。
3. **不评估并发**：调度器已按请求隔离、轨迹库已加锁并有并发单测，但**未做并发压测** —— 只能说"逻辑可证"，不能说"支持并发评测"。
4. **引用支持度与成本指标未实现**，v1.0 只覆盖正确性与拒答两类。
5. **L3 未做部分分**：答案错了就是错，不区分"思路对但算错"。
