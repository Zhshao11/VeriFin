## 一、这个项目是什么

**财报核验 Agent**——面向 A 股上市公司年报的**带证据溯源的数字核验 Agent**。校招面试用。

一句话判据：**给它一份年报和一个财务问题，它要么给出每个数字都能点到 PDF 具体页码与原文片段的答案，要么明确拒答。中间不允许编造。**

### 必须达成的 5 件事（面试判分点）

| # | 要求 | 当前状态 |
|---|---|---|
| 1 | PDF 解析（表格 / 公式 / 跨页） | 🟢 跨页拼接已实现并回归（p58–p61 → 1 张逻辑表，共 5 张） |
| 2 | 证据可溯源（六元组：公司/期间/指标/数值/单位/页码+原文片段） | 🟢 六元组 + span 校验 + 绝对坐标，已在真实年报上端到端产出 |
| 3 | 财务勾稽核验（≥5 个公式） | 🟢 公式注册表已实现（F1–F6），恒等式已在真实年报上 PASS |
| 4 | 计算精度（Decimal，禁 float） | 🟢 已实现，float 会被拒绝 |
| 5 | 公开评测（FinanceBench 50 题 + 1 项消融） | 🔴 未开始（**下一阶段**） |

### 硬约束

- 技术栈**只锁 Python 3.11+ 与 LLM**（实际用 3.13.12），其余全部调研后自选
- 单进程、本地跑、不上微服务、不引入向量库
- 数据集用 FinanceBench（用户已拍板；注意其 CC-BY-NC-4.0 非商用限制，评测报告须写明）

## 二、不可违反的 4 条设计红线

1. **LLM 不产生任何数字** —— 数值只能来自 span 校验通过的原文
2. **LLM 不做任何算术** —— 算术全部走 `Decimal` + 公式注册表
3. **LLM 无权决定拒答与否** —— 六元组缺字段即**程序级**拒答，不靠提示词
4. **embedding 不参与数字精确匹配** —— 必须先做数字归一化（去千分位 / 全角半角 / 单位分离）

> 这 4 条是"这个项目为什么不是套壳 RAG"的答案。任何设计不能削弱它们。

| LLM | **`glm-5.3`**（用户提供的中转端点，`https://llm.goaichat.top/v1`） | 三项能力实测通过 |
| 存储 | **SQLite 单文件**（含 `agent_trace` 执行轨迹库） | ✅ 已实现 |
| 计算 | **`decimal.Decimal`**，禁 float | 已实现 |

### ⚠️ 三条已实测的强制约定（不遵守会静默出错）

1. **查询进 FTS5 前必须 jieba 切词**：`match(" OR ".join(tokenize(q)))`。
   裸串 `match('资产总计')` 会返回 **0 且不报错**（实测），被上层误判成"报告里没这个数"，触发本不该有的拒答。
   MinerU doclib 的存储文本已用 jieba 预分词（与我们的 jieba 445/445 重合），所以只需修查询侧。
2. **必须先注入财务专用词典再切词**（`verifin/lexicon.py`）。
   jieba 默认词典不认识会计科目，会把「营业收入」切成 营业+收入，
   实际效果是排序被 `营业外收入` 抢走——**取错科目等于取错数**，且不报错。
3. **容差必须由报表披露单位推导**：`容差 = 参与科目数 × 0.5 × 报表单位`，**不得硬编码 0.01**。

### 不做整体 fork 的开源平台（已调研并否决，避免重复劳动）

RAGFlow（5 容器 / C++Go 混合，仅留作解析降级）、Dify 与 FastGPT（改版 Apache-2.0 有商用限制）、
QAnything（AGPL 传染）、Verba（已归档）、KAG（需建 KG 且引用只到 chunk 级）、
FinRobot / FinGPT / OpenBB / TradingAgents（场景错配）。
唯一备选 fork 对象是 **kotaemon**（Apache-2.0，页码级引用高亮），但只建议抠其引用 UI 组件。

## 五、已知缺陷（都已定位到根因，不是"感觉有问题"）

> 逐条详情见 `docs/技术问题留档.md`（含原方案、短板、实测证据、解决方案、残留限制）。

| # | 缺陷 | 现象 | 状态 |
|---|---|---|---|
| 1 | 跨页表格不合并，续页不重复表头 | 合并资产负债表跨 p58–p61 被切成 4 个 `<table>`，表头只在 p58 | ✅ 已解决（`tables.py`） |
| 2 | 同文档混用两种表格格式 | p58–p60 是 HTML `<table>`，p61 起变 markdown 管道表 | ✅ 已解决 |
| 3 | FTS5 查询侧未切词 | `match('资产总计')` → 0，静默 | ✅ 已解决（`retrieval.py`） |
| 4 | doclib 不存 bbox | schema 无坐标列 → 无法画框高亮 | ✅ 已解决（`geometry.py`） |
| 5 | 结构化输出丢字段 | 端点接受 `strict:true` 但不强制必填，实测 7→5 | ✅ 程序级兜底 + 拒答 |
| 6 | **端点无 embedding 能力** | `/v1/embeddings` 全 404 → 原方案的「numpy 向量」悬空 | ✅ 已解决（可插拔 `Embedder` + 本地 TF-IDF） |
| 7 | **jieba 不认会计科目** | 「营业收入」被切成 营业+收入 → 排名被 `营业外收入` 抢走 | ✅ 已解决（`lexicon.py`） |
| 8 | **「附注」列被当数值** | `未分配利润 = 39`，且能通过 span 校验 | ✅ 已解决（由表头推导数值列） |
| 9 | 长科目名在 PDF 里折行 | `所有者权益（或股东权益）合计` 跨两行 → 定位失败 | ✅ 已解决（block 内跨行拼接） |
| 10 | 坐标去重只比 x | 上下相邻行 x 相近 → 真目标被吞 | ✅ 已解决（四边都比） |
| 10b | **公式规范名 ≠ 报表披露名**（P-012） | F1 操作数「所有者权益合计」在报表里叫「所有者权益（或股东权益）合计」→ 判成缺操作数 WARN，与"取到但算不平"混同 | ✅ 已解决（`LABEL_ALIAS` 对齐层，只做精确+别名，不做模糊包含） |
| 14 | **原选型的「function calling 自主调工具」与红线 #1 冲突**（P-013） | function calling 必然让 LLM 产出参数；`verify_span(claimed_value=...)` 的参数就是待校验的数值 → 等于把数值生成权交出去 | ✅ 已解决（改为「LLM 只选节点 + 图填参数」，框架也由 Pydantic AI 换为自写显式图） |
| 15 | **兜底策略自环（反复选中同一节点）**（P-014） | `SEARCH` 在自身合法后继里，兜底策略每步都重选它 → 12 步预算被自环吃光 → `ABORT` | ✅ 已解决（跳过 visited，不主动走回边） |
| 16 | **LLM 预算写成全局计数**（P-015） | planner 被多个问题复用 → 第二个问题起静默降级为兜底策略，LLM 调用数为 0 | ✅ 已解决（`planner.reset()` 按运行重置；Web 端调度器改为每请求新建） |
| 11 | 首次解析 `BrokenProcessPool` | 子进程 `Errno 9`，服务自愈 | ⚙️ 环境类，重试即成功，**不留档** |
| 12 | pip 无法解包 sdist / pytest `tmp_path` 建不出 | `PermissionError: EEXIST` | ⚙️ 环境类，已绕行，**不留档** |
| 13 | MinerU 三个开关 | `--pages` 默认前 10 页；`local.mode` 默认 `disabled` | ⚙️ 配置类，**不留档** |
| 17 | LLM 端点 `429` 频率限制 | 端点侧限流 | ⚙️ 环境类，降级到兜底策略，**不留档**（前提是 15 已修） |

## 八、用户偏好（协作方式）

- **每轮回复必须包含三部分**：① 已完成 / 待完成清单；② 非工程实现问题的留档
  （设计层面「原方案短板 → 换方法解决」写入 `docs/技术问题留档.md`；
  缺库 / 配置缺失 / 环境崩溃 / 纯手误 bug **不留档**）；③ 下一步计划。
- 用户在意**「这算不算一个 Agent 项目」**，会主动质疑设计是否偏离 Agent 定位。
  汇报时必须正面回答 Agent 判据（工具自主选择 / 条件边 / 预算终止 / 观察可重放 / 拒答是一种状态），不能只讲工程取舍。
- 用户希望**基于开源项目二次开发**而非从零。给出"不用某框架"的结论时，必须同时给可 fork 的候选与理由。
- 用户在意**实测证据**——结论要有实跑输出，不能是"应该可以"。
